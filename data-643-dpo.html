9.3 Direct Preference Optimization

DATA 443/643 · Week 9 · PDF · Slides

Same pairs. Implicit r = β log(π/π_ref). Z(x) cancels. Offline.

These notes match the lecture slides. Use (slides) on the course hub for the deck.

Direct Preference Optimization (DPO) (Rafailov et al., 2023) fits a policy to chosen/rejected pairs without training an RM and without PPO. The reward is written in closed form from the policy and a frozen reference, then the Bradley–Terry model becomes a classification loss on logits.

1. What DPO is

RLHF solves maxπ𝔼[r]−βKL(π‖πref) with a learned RM and an on-policy loop. DPO uses the same preference pairs and skips both the RM and PPO. Under Bradley–Terry, the optimal reward can be written from the policy and a frozen reference,

r(x,y)=βlogπ(y∣x)πref(y∣x)+const(x).

Plug that into the RM logistic loss and the r parameters disappear. You train πθ directly, offline. The derived reward has a partition Z(x) that cancels because Bradley–Terry only sees a difference. KTO and IPO sit in the same family; this hour is DPO.

If πθ=πref, both log-ratios are 0, the argument of σ is 0, and σ(0)=1/2. Then ℒDPO=log2≈0.693. That is the start of training, not a bug. Lab 9 will compute this on toy scalar logits, not on an LLM.

2. Why we use it

RLHF’s PPO stage is heavy: sampling, a critic, a moving policy, stale rollouts. DPO is a classification loss on logits of yw and yl. You have pairs, a GPU, and no appetite for a PPO stack. Offline: the pair set is fixed, so you do not explore new y unless you collect more.

That is also the limit. If the SFT model never proposed good yw, DPO cannot invent them from nothing. PPO can sample new y that were not in the pair file; offline DPO cannot. Implicit reward can still overfit the pair set. Report β, the reference checkpoint, and a held-out preference accuracy (how often πθ assigns higher log-prob to yw than to yl). That number is not “the model is aligned”; it is “the model copied this rater.”

3. Architecture

Two networks, one frozen: policy πθ and reference πref (usually SFT). No critic. No sampling-in-the-loop required. You need log-probabilities of both completions under πθ and under πref. The reference stays frozen. Dropping πref because “there is no RM” removes the leash; the reference is the leash.

The data path is the same pair file as note 9.1. The compute path is a forward on yw and a forward on yl for each of πθ and πref (four logprob sums, or two if you cache the frozen reference). There is no RM head.

4. How it works, step by step

  1. Start from SFT. Freeze that checkpoint as πref. Copy it as πθ.
  2. For each pair (x,yw,yl), compute log-prob of both completions under both models.
  3. Form the two log-ratios log(πθ/πref) and subtract loser from winner. Scale by β.
  4. Push that difference through σ and take −log. Gradient raises relative mass on yw versus yl, compared with the reference.
  5. Absolute log-prob can fall on both sequences; relative log-prob is what DPO scores. Write the argument of σ as β(Δlogπθ−Δlogπref) if it helps.

At init, πθ=πref and the loss is log2. After a few steps the winner log-ratio should exceed the loser log-ratio. The frozen reference is still there: without it, πθ can raise both log-probs or collapse. β is the same kind of leash as in RLHF: it scales how hard you push away from πref.

5. Mathematical formulas

Closed-form reward, then DPO loss:

r(x,y)=βlogπ(y∣x)πref(y∣x)+const(x), ℒDPO=−logσ(βlogπθ(yw∣x)πref(yw∣x)−βlogπθ(yl∣x)πref(yl∣x)).

If πθ=πref, both log-ratios vanish and ℒDPO=log2. After a few steps, toy log-probs (sums over tokens): logπθ(yw)=−2.0, logπref(yw)=−2.5, logπθ(yl)=−3.0, logπref(yl)=−2.0. Log-ratio winner: −2.0−(−2.5)=0.5. Log-ratio loser: −3.0−(−2.0)=−1.0. Difference 0.5−(−1.0)=1.5. σ(1.5)≈0.818, loss −log0.818≈0.201.

6. Positive points and negative points

Positive.

  • Offline classification loss: no RM head, no PPO loop, no on-policy sampling.
  • Same pair file as the RM lecture; the closed-form r is why the RM can disappear.
  • Init loss log2 is a checkable number (Lab 9).
  • β is still an explicit leash toward πref.

Negative.

  • Still needs pairs and a frozen reference. Dropping the reference is not a simplification.
  • Can overfit the pair set. Held-out preference accuracy is “copied this rater,” not “aligned.”
  • Not magic if the pairs are noisy. Two wrong answers still define an order.
  • Offline: cannot invent replies the SFT model never wrote. PPO can sample new y.
  • Absolute log-prob can fall on both sequences; if you only watch that, you will think training failed.

When not to. If you need on-policy exploration of completions that are not in the file, stay with RLHF. If you have no SFT reference, you do not have DPO’s leash.

7. Teaching this note

About 35–40 minutes at the board: write implicit r, plug into σ, compute σ(0)=1/2. Play the Deep Dive preference / RLHF segment 2:48:26–3:09:39. Lab 9 section 2 is the toy DPO scalar.

8. Worked example

Let β=1. Suppose at init πθ=πref. Then

logπθ(yw)πref(yw)−logπθ(yl)πref(yl)=0,

so ℒ=−logσ(0)=−log(1/2)=log2.

After a few steps, toy log-probs (sums over tokens): logπθ(yw)=−2.0, logπref(yw)=−2.5, logπθ(yl)=−3.0, logπref(yl)=−2.0. Log-ratio winner: −2.0−(−2.5)=0.5. Log-ratio loser: −3.0−(−2.0)=−1.0. Difference 0.5−(−1.0)=1.5. σ(1.5)≈0.818, loss −log0.818≈0.201.

The frozen reference is still there: without it, πθ can raise both log-probs or collapse. PPO can sample new y that were not in the pair file; offline DPO cannot.

9. Where students get stuck

  • Forgetting σ(0)=1/2 when πθ=πref at step 0.
  • Dropping πref because “there is no RM.” The reference is the leash.
  • Expecting DPO to invent replies the SFT model never wrote.

11. Practice

  1. If πθ=πref, what is ℒDPO? (Compute σ(0).)

  2. Why do you still keep a frozen reference if there is no RM?

  3. Name one thing PPO can do that offline DPO cannot, given a fixed pair file.

  4. β=2, winner log-ratio 0.4, loser log-ratio 0.1. What is the argument of σ, and is the loss smaller or larger than log2?

  5. Both completions have log-prob −10 under πθ and under πref. What is the DPO loss, and what did the policy fail to learn yet?
